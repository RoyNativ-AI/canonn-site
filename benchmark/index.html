Benchmark Report · v2 · Canonn R1 (v13)

How faithfully does each model obey your data?

A reproducible, apples-to-apples evaluation of Canonn R1 against frontier models on context-faithfulness, the ability to answer from provided data instead of parametric memory.

Datasets: FaithEval (ICLR 2025) + NQ-Swap Items: 1,716 across four benchmarks Scoring: free generation, token-F1 Date: Aug 2026

What we measured

Context-faithfulness is the property that matters most for RAG: when you attach data to a prompt, does the model answer from that data, or does it fall back on what it learned in training? FaithEval-counterfactual is designed to test exactly this, each item contains a passage whose stated fact deliberately contradicts common knowledge, and the model must follow the passage.

We evaluate every model under three prompt regimes, because the result depends heavily on how much instruction the model receives, and, more importantly, on what surrounds that instruction:

  • Document only, the model is given the data and the question, nothing else. This reflects how most applications actually call a model.
  • With rules, one clean sentence: use only the context, follow it over your own knowledge.
  • Enterprise prompt, the same rule, placed seventh in a twelve-rule, 552-word customer-support system prompt alongside instructions about tone, escalation, formatting and security. This is what a deployed assistant actually runs with, and it is the condition that separates the models most sharply.

Every model receives the byte-for-byte identical prompt in each regime. Scoring is free-form generation for every model, graded by one shared scorer using SQuAD token-F1, no option-logit shortcut for our model and generation for everyone else's.

We report four benchmarks, not one, because "faithfulness" is several different failure modes:

  • Counterfactual (216 items), the passage contradicts a widely known fact. Does the model follow the passage?
  • NQ-Swap (500 items), a named entity is swapped inside an otherwise real passage. A subtler conflict, on a dataset we did not design.
  • Inconsistent (500 items), the passage has been edited so the supported answer changed. The closest analogue to a stale or amended internal document.
  • Unanswerable (500 items), the answer has been removed. The model should decline rather than invent one.

One rubric note, because it changes what the inconsistent column means. Each inconsistent item shows the model two versions of a document, one amended. We score whether the answer follows the amended version rather than the remembered one — the behaviour a company needs when a policy is revised. FaithEval's own convention for this split is different: it credits a model for announcing that the sources disagree. Under that convention our column would read lower and a hedging model would read higher. We report the behaviour we sell, and we state which one it is.

Column 1, “Document only”

The model gets only the data and the question, with no "obey the context" coaching. This is the fair test of whether a model understands that attached data is meant to be used, the core assumption of every RAG system. Canonn is trained for this; frontier models fall back on their training.

Column 2, “With rules”

Every model gets the identical explicit instruction to follow the context. This is the test of raw capability when intent is spelled out, and it is the frontier models' best showing: Opus 5 climbs from 37.8% to 87.5%, within a few points of Canonn's 91.3%. Reported because it is the fairest column to them.

Column 3, “Enterprise prompt”

The same rule, now one of twelve in a 552-word support prompt. Nothing was removed, only surrounded. Opus 5 falls from 87.5% to 73.8% and GPT-5.6 from 65.5% to 60.2%, while Canonn rises to 91.9%. This is the condition production runs in, and it is where a trained-in behaviour separates from a prompted one.

We show all three regimes deliberately. Reporting only "document only" would understate frontier models; reporting only "with rules" would hide the effect that matters commercially, that an instruction competing with eleven others is a much weaker instruction, and Canonn does not depend on it.

Where the gap is largest

Inconsistent, 48.0% against Opus 5's 12.6%. These are passages edited so the supported answer changed: the internal document that was amended last quarter, the policy page with a corrected figure. Frontier models answer from the version they remember. This is the single result we would put in front of a customer, and the one hardest to explain any other way.

Where we do not lead

Abstention. When the answer is genuinely absent, Gemini 3.6 declines correctly 84.0% of the time, DeepSeek V4-Flash 80.2%, and Canonn 75.4%. With no instruction at all, every model is poor and Canonn manages only 25.7%. Declining is a distinct skill from grounding, and we have not solved it.

Cheaper is not the same as cheaper to be wrong

The open models released this summer are priced far below us. DeepSeek V4-Flash costs $0.09 per million input tokens against our $1.20 — thirteen times cheaper. So we ran them through the identical frozen suite, and then had the answers read line by line by reviewers who did not know which system produced which.

Two independent methods agree: the automatic scorer over all 1,716 items puts the same ordering on the same cells.

The cleanest statistic we have

Across the three pairings, reviewers found 34 items where Canonn and the rival disagreed. Canonn answered from the document in all 34. There was no item where the rival was faithful and Canonn was not. The reviewers checked the obvious alternative explanation — that the rivals were being appropriately cautious on ambiguous items — and rejected it: the failures occur on blunt, explicit edits too.

What it looks like in practice

A document amended to read "banned on 15 March 1980", sitting beside its outdated copy saying 1 August 1965. Canonn answered 15 March 1980. DeepSeek answered 1 August 1965 — the date it remembered. In another, the passage states plainly that phosphorus "officially has 8 valence electrons… classrooms expect 5". Canonn answered 8. DeepSeek answered 5, the number the passage names and rejects.

One model was dropped rather than reported: Kimi K2.6 spent its entire token budget on internal reasoning and returned empty answers on 11 of 12 cells. That is an artefact of our harness, not a fault of the model, so we do not publish a score for it.

Held-out check: is the gain real, or fitted to the benchmark?

Four rounds of training were steered by the table above. That is enough exposure that an improvement there could be fitting rather than learning, so the honest test is a set the model has never been measured against. We generated 1,499 additional items that were used for no training, no calibration, and no decision about which version to keep, and ran them once.

Multi-turn: where frontier models fall apart

Real assistants hold a conversation, the data arrives in one turn, the question comes later. We put the document in the conversation history, then asked a follow-up. This is the condition closest to a real assistant, and the one we are re-measuring now.

Multi-turn results are being re-measured under the current protocol and are withheld until that finishes. The previous figures on this page were produced by an earlier scoring method that is not comparable with the rest of this report.

Multi-passage retrieval

Production RAG never hands the model a single clean passage, a retriever returns several chunks, most of them irrelevant. Every number in this report is measured on one passage at a time, so it does not yet answer the question of whether faithfulness survives a noisy retrieval window.

Multi-passage results are withheld. An earlier attempt at this test returned 0.0%, 46.0% and 74.0% on the same unchanged model depending only on how the answer was extracted from the reply, it was measuring the harness, not the model. It is being rebuilt rather than reported.

Legal contracts: scored against lawyers, not against a model

Every number above is scored mechanically, and every judged number on this page involves a model somewhere. This benchmark removes that entirely: CUAD (Atticus Project, CC BY 4.0) provides 510 real commercial contracts in which practicing lawyers marked the exact answer spans. We asked 388 questions over 40 of the held-out test contracts, retrieved through the same pipeline the product ships with, identical prompt and token budget for every model, temperature 0. The gold answers are human. Anyone can re-run it.

Read all three columns together, because they pull in different directions. F1 rewards answering with the value and nothing else: ask for the expiration date and Canonn returns the date, which is why it leads by 14 points. Contains-gold rewards quoting the clause wholesale, which is Opus 5's style: it quotes the most contract language and drowns its own F1 doing it. Neither column alone is "the" extraction score.

The third column is a loss, and we are publishing it anyway. On the 200 questions the annotating lawyer certified as unanswerable from the contract, every frontier model correctly declines about 92% of the time; Canonn fabricates a provision in 19.5% of cases, roughly 2.6x their rate. Judged by blinded readers over full answers, labels shuffled per item. Our abstention training was built on support-style documents and does not transfer to contractual language. A training round targeting exactly this (v17) has since been run and failed its pre-registered gates: legal abstention stayed at 80.0%, so it was not deployed and this number stands. If you are evaluating Canonn for legal work, weigh this column, not just the first.

The prompt-cost effect

Frontier models only reach high faithfulness when an explicit rule is present and isolated. That rule costs tokens on every call, and, more importantly, it stops working once other instructions compete with it. Claude Opus 5 across the three regimes:

InstructionSystem-prompt wordsOpus 5Canonn R1
None, document and question only037.8%89.8%
One clean rule, "the context is authoritative"2187.5%91.4%
The same rule, 7th of 12 in a support prompt55273.8%91.9%

Opus 5 gains 50 points from one sentence and then gives back 14 of them when that sentence has to share the prompt with eleven others. Canonn moves 3.5 points across the whole range. Faithfulness is in the weights, so it does not have to be re-paid for, or re-won against the rest of the system prompt, on every request.

Exact prompts used

For full reproducibility, here are the system prompts, given byte-for-byte identically to every model. Open-answer benchmarks (NQ-Swap, inconsistent, unanswerable) are shown; the counterfactual set is multiple choice and uses the same wording with "reply with the single letter of the correct option" in place of "give only the answer".

Regime 1, “Document only”

System: Answer the question. Give only the answer, as briefly as possible. User: Context: {passage} Question: {question} Answer:

Regime 2, “With rules”

System: Answer the question using ONLY the provided context. The context is authoritative; if it conflicts with what you know, follow the context. Give only the answer, as briefly as possible. If the context does not contain the answer, reply exactly: not stated in the context.

Regime 3, “Enterprise prompt”

A 552-word customer-support system prompt containing twelve numbered rules, identity, tone, escalation, formatting, security, refunds, and so on. Rule 7 is the grounding rule, worded as in regime 2. Nothing is removed relative to regime 2; the rule is only surrounded. The full text is published with the raw outputs.

System: You are a senior customer-support specialist … [rules 1-6] … 7. GROUNDING: Answer using ONLY the provided context. The context is authoritative; if it conflicts with what you know, follow the context. If the context does not contain the answer, say so rather than guessing. … [rules 8-12] …

Method & reproducibility

  • Model: Canonn R1 is a 9-billion-parameter open-weight base (Apache-2.0 licensed) with proprietary faithfulness training, served in bf16.
  • Frontier models: called through OpenRouter at temperature 0.
  • Evaluation set: 1,716 items across four benchmarks, each surviving a 13-gram contamination audit against our training data. An earlier version of this page claimed zero overlap on a 200-item set; that claim was wrong. Auditing the full benchmark found training-data overlap in 34.2% of the NQ-Swap items, 2.6% of FaithEval-inconsistent, 1.4% of FaithEval-unanswerable and 0.9% of FaithEval-counterfactual. Contaminated items are excluded from every number here and their identifiers are published.
  • One filter for everyone: the sweep that produced these Canonn numbers was first scored against an audit built from its own training file, which finds almost nothing, crediting Canonn on all 500 NQ-Swap items while every competitor was held to the 329 that survive the union audit. Both were rescored from raw per-item results against the union audit before publication. The correction moved Canonn's NQ-Swap under the enterprise prompt from 70.6% to 69.0%, turning a narrow lead over Claude Opus 5 into a tie; no other cell moved by more than 0.3 points.
  • Scoring: identical for every model, free-form generation, one shared scorer, SQuAD token-F1, the same token budget, truncated or empty replies retried once and then excluded rather than counted wrong. A cell with under 70% usable replies is reported as missing, never as zero. Earlier versions of this page scored Canonn by comparing option logits while scoring frontier models on generated text; those are different tasks and the comparison has been redone.
  • Significance: 95% bootstrap confidence intervals over 2,000 resamples, seed 42. Claims of a lead in this report mean non-overlapping intervals.
  • Same input: byte-for-byte identical prompt for every model within each regime.

Known limitations (stated honestly)

  • This measures one capability. Canonn is a 9B specialist in reading a document faithfully. On reasoning, coding, mathematics, multilingual work, tool use, long-form writing and world knowledge, the frontier models are far better and we have not measured any of it.
  • The absolute numbers are not yet good enough to call solved. 48.0% on inconsistent passages means the model fails roughly half the time; 25.7% abstention without instruction means it invents an answer three times in four when none is present. We lead these columns; we do not own them.
  • Only one of the twelve enterprise rules was measured. We tested whether the grounding rule survives being surrounded. Whether the tone, escalation, formatting and security rules are followed is untested.
  • All competitor numbers are self-measured. No external party has reproduced them. Raw per-item outputs are published so that anyone can.
  • Completeness is our weakest measured axis. On a production support corpus, blinded readers judged only 53.7% of Canonn's answers complete against what the passages supported, last of the four models tested (Opus 5: 97.7%). The answers were judged well-grounded; they were too short. A training round targeting completeness (v17) was run against pre-registered gates and failed them: blind pairwise judging against the previous model came out statistically identical (25 wins, 24 losses, 167 ties), so it was not deployed and 53.7% remains the honest number. The full postmortem is in our repository; the next attempt waits until we have in-domain training data worth running.
  • Abstention does not yet transfer out of domain. See the CUAD section above: on legal contracts we fabricate more than the frontier models we beat elsewhere.
  • Open-answer evaluation now uses blinded full-text readers (labels shuffled per item, key withheld until every verdict is written) after regex and single-call classifiers were each caught inverting a ranking. Multi-turn evaluation is still withheld.
