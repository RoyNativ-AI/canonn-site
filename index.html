Your AI ignores your data.

The API

One endpoint. Drop-in.

Canonn R1 is served through an OpenAI-compatible API. If your stack speaks to OpenAI, it already speaks to Canonn, change the base URL and you're grounded.

→ OpenAI-compatible

Same request shape, same streaming. Works with the OpenAI SDKs, LangChain, LlamaIndex, swap base_url and go.

→ Extraction mode by default

Every answer is decoded against your data twice, once with it, once without, and keeps only what the data supports.

→ Routed under the hood

Short prompts and long production prompts are served by different experts, picked per request. You call one model name: canonn-r1.

→ Cloud or yours

Use our endpoint, or run the same weights on your own GPU inside your network. Same API either way.

POST https://api.canonn.ai/v1/chat/completions
canonn, zsh
# any OpenAI client works, just point it at Canonn
curl https://api.canonn.ai/v1/chat/completions \
  -H "Authorization: Bearer $CANONN_API_KEY" \
  -d '{
    "model": "canonn-r1",
    "messages": [
      {"role":"system","content":"Refund window: 45 days.
        In-app purchases: 5 days."},
      {"role":"user","content":"How long do I have?"}
    ]
  }'

# response, grounded, no invented policy
{"choices":[{"message":{
  "content": "45 days from purchase, or 5
              days for in-app purchases."}}]}
